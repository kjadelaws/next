# Prompt History & Development Process

## Project: NEXT

Throughout this project, I used both ChatGPT and Replit AI as learning partners. Rather than asking AI to build the application for me, I used it to brainstorm ideas, organize my thinking, understand code, troubleshoot problems, and review my work. The prompts below highlight key moments in my development process and demonstrate how I collaborated with AI from planning through deployment.

---

# 1. Defining the Project

### Prompt

> I will be creating a project (I am not sure what it is yet) for an educational submission for possible acceptance into a coding and AI bootcamp.

### Why I Asked

I knew I wanted to build something meaningful, but I wasn't sure what problem I should solve or how large the project should be.

### Outcome

AI helped me think through several ideas, ask the right planning questions, and narrow my focus. Through those conversations I decided to build **NEXT**, a simple web application that helps people returning home from incarceration identify their next step without feeling overwhelmed.

---

# 2. Defining the Scope

### Prompt

> That seems like a very big project to me. Maybe if you can break it down for me or let's make it a bit smaller.

### Why I Asked

My original vision was much larger than what I could realistically complete for this project. I wanted to learn how to build a Minimum Viable Product (MVP).

### Outcome

Instead of trying to solve every reentry challenge, I narrowed the application to three core areas:

- Essential Documents
- Employment
- Transportation

This became the foundation of Version 1 of NEXT.

---

# 3. Learning GitHub

### Prompt

> It wants a description up to 350 words.

### Why I Asked

I was creating my first GitHub repository and wasn't sure what information GitHub expected.

### Outcome

AI explained that GitHub was asking for **350 characters**, not words, and helped me create a concise project description. I also learned what repositories, commits, and project files are and how they work together.

---

# 4. Building My First HTML Page

### Prompt

> Is this right?

### Why I Asked

After typing my first HTML page, I wanted to verify that I had entered everything correctly before continuing.

### Outcome

AI identified a mistake in my HTML structure and explained why it happened instead of simply correcting it. This became my first experience debugging code.

---

# 5. Understanding the Code

### Prompt

> Can we pause here and let's break down what we did and why—in small groups?

### Why I Asked

I realized I was learning faster when I understood *why* something worked instead of simply copying code.

### Outcome

AI explained the purpose of each project file:

- index.html (structure)
- style.css (appearance)
- script.js (behavior)

This helped me understand how the different parts of a web application work together.

---

# 6. Designing the User Experience

### Prompt

> We haven't discussed style. What if I want softer colors? Can you ask me how I want it to look and then we will write it?

### Why I Asked

I wanted the visual design to support the purpose of the application instead of simply accepting default colors.

### Outcome

Rather than choosing colors first, I thought about how I wanted users to feel:

> "At ease, hopeful, and confident that they will be able to get through this next part."

Based on that design goal, I selected a softer color palette that better reflected the mission of NEXT.

---

# 7. Improving the Product

### Prompt

> Wait. I want the logo and wording on a first page with the About button, and we will need to add a "Next" button that takes the user to the second page.

### Why I Asked

After seeing my application running for the first time, I realized I wanted users to understand the purpose of NEXT before immediately viewing the resource guides.

### Outcome

I redesigned the application by adding:

- A landing page
- The NEXT logo
- An About section
- A Begin button

This created a more intentional user experience and better communicated the purpose behind the project.

---

# 8. Learning Professional Workflow

### Prompt

> Why am I repasting everything inside the body?

### Why I Asked

As the application grew, I wanted to understand why I was making large structural changes instead of editing individual sections.

### Outcome

AI explained how restructuring affects multiple connected parts of an application and introduced me to Replit as a development environment. I also learned the difference between a code editor and GitHub, and how commits preserve the history of my work.

---

# 9. Debugging

### Prompt

> My logo isn't showing up.

### Why I Asked

After uploading my logo, it wasn't displaying correctly and I wanted to understand why.

### Outcome

I learned that filenames and file paths must match exactly for images to display correctly. This taught me how web applications locate external files and assets.

---

# 10. Verification Before Submission

### Prompt

> I want to verify each section of code. I want to understand what is happening.

### Why I Asked

Before submitting my project, I wanted to make sure I understood how my application worked instead of simply knowing that it worked.

### Outcome

AI reviewed each section of my project with me, explaining the purpose of the HTML, CSS, JavaScript, navigation, and overall project structure. This gave me confidence that I could explain my work during an admissions interview.

---

# Reflection

One of the biggest lessons I learned during this project was that AI is most effective when I clearly define the problem first. As my understanding of the application grew, my prompts became more specific, and AI became a better collaborator rather than simply a code generator.

Throughout this project I used AI to brainstorm ideas, organize information, explain coding concepts, troubleshoot problems, review my work, and challenge my own thinking. I frequently asked follow-up questions, paused to understand concepts before moving forward, and made product decisions based on the experience I wanted users to have.

Building NEXT taught me much more than HTML, CSS, JavaScript, and GitHub. It showed me how to think through problems, build incrementally, test my work, and use AI as a partner in the engineering process. Most importantly, it gave me confidence that I can continue learning and building technology that creates meaningful value for others.
